# 学祭飲食POSシステム（gakusai-pos）

学祭の飲食模擬店向けのPOS（受付・会計）とKDS（厨房の注文表示）です。会計と同時に注文を厨房へ到着順で届け、作り忘れ・順番ミス・受け渡し間違いを防ぎます。

## 1. 概要と3台の構成

```text
            学内Wi-Fi
 ┌──────────────┬──────────────┐
 PC1 受付（店舗）  PC2 厨房（店舗）   PC3 管理兼サーバー（部室）
 Chrome           Chrome            Pythonサーバー + Chrome
 ノートPC等       スマホ等           https://<PC3のIP>:8443/
```

| 端末 | 役割 | 開くURL |
| --- | --- | --- |
| PC1 受付 | 商品入力（QRカメラ・商品ボタン）、会計、取消 | `https://<PC3のIP>:8443/reception` |
| PC2 厨房 | 注文表示、調理開始・受渡完了、売切切替 | `https://<PC3のIP>:8443/kitchen` |
| PC3 管理 | サーバー、商品・設定、ログ、売上集計、レジ締め、バックアップ | `http://localhost:8080/admin` |

- データ（注文・商品・設定・ログ）はPC3の `data/pos.db`（SQLite）1か所にあります。
- PC1・PC2はChromeさえあればよく、スマートフォンやタブレットにも置き換えられます。
- 管理画面・管理APIはPC3自身からしか開けません。PC1・PC2はパスコードで登録した端末だけが使えます。
- 支払いは学内通貨（50円の金券）のみ。価格は50円の倍数なので、おつりは発生しません。

## 2. 必要なもの

- PC3：Windows または macOS。[uv](https://docs.astral.sh/uv/)（Python 3.12は uv が自動で用意します）
- PC1・PC2：Google Chrome（PC・Android・iPhone・iPad）。PC1はカメラがなくても使えます
- 学内Wi-Fi（3台が同じネットワークで通信できること）
- QRカードの印刷用プリンタ（A4）
- あれば：バックアップ用のUSBメモリ

### uv のインストール

Windows（PowerShell）:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

macOS（ターミナル）:

```sh
curl -LsSf https://astral.sh/uv/install.sh | sh
```

インストール後、ターミナルを開き直して `uv --version` で確認します。

## 3. セットアップ（PC3）

このフォルダで次を実行します（インターネット接続が必要なのはこの `uv sync` だけです）。

```sh
uv sync
uv run gakusai-pos init-db
```

`init-db` を初めて実行すると **初期パスコード（6桁）** が表示されます。PC1・PC2の登録に使うので控えてください（管理画面の「設定」で変更できます。忘れたら `uv run gakusai-pos reset-passcode` で再設定）。`init-db` を省略しても、`serve` の初回起動時に同じことが行われます。

> OneDrive などの同期フォルダに置いている場合、`pyproject.toml` の `link-mode = "copy"` 設定でインストールできるようにしてあります。

## 4. 起動

```sh
uv run gakusai-pos serve --port 8443
```

起動すると、ターミナルに次が表示されます。

- 管理画面のURL：`http://localhost:8080/admin`（PC3のChromeで開く。PC3自身からだけ開ける http の入口なので、証明書の警告は出ません）
- 受付・厨房用のURL：`https://<PC3のIP>:8443/` と、そのQRコード

管理画面の「ホーム」にも同じURLとQRコードが常に表示されます。**学内Wi-FiではPC3のIPアドレスがつなぎ直すたびに変わることがあります**。変わったら新しいURLを店舗に伝え、PC1・PC2で開き直してください。

終了は `Ctrl+C`。止めても、受渡前の注文を含めすべてDBに残り、再起動すれば元に戻ります。

その他のオプション：`--host`（既定 `0.0.0.0`）、`--data-dir`（既定 `./data`。環境変数 `GAKUSAI_POS_DATA` でも指定可）、`--admin-port`（管理画面の http 版のポート。既定 `8080`、`0` で無効。使用中なら自動で無効になり、`https://localhost:8443/admin` を使います）、`--http`（開発用。カメラは使えません）。

## 5. PC1・PC2の接続手順

1. PC3の管理画面に出ているQRコードをスマホで読む（またはURLをChromeに入力）。
2. **証明書の警告**（「この接続ではプライバシーが保護されません」）が出たら、「詳細設定」→「<IPアドレス> にアクセスする（安全ではありません）」。自己署名証明書のため、端末ごとに初回だけ出ます。スマホ版Chromeも同じ操作です。
3. 役割（PC1 受付 / PC2 厨房）を選び、パスコードを入力して「登録して開く」。以後はChromeが記憶します。
4. 受付端末では **カメラの使用を「許可」** します。断ってしまったら、アドレスバー左のアイコン →「カメラ」を許可にして再読み込み。
   - ノートPCの内蔵カメラは前面なので「左右反転」がオンだと見やすいです。スマホ・タブレットでは「背面カメラへ」を押すと読みやすくなります。選んだ設定は端末に記憶されます。
   - カメラが使えなくても、商品ボタンだけで全操作ができます（「カメラ OFF」でボタンが画面いっぱいに広がります）。

画面上部に **赤帯（接続が切れています）** が出たら、Wi-Fiを確認してください。自動で再接続し、最新の状態を取り直します。

## 6. PCの事前設定

### ファイアウォールでポートを許可（PC3）

Windows：初回起動時に「Windows セキュリティの重要な警告」が出たら「プライベート ネットワーク」と「パブリック ネットワーク」の両方を許可します（学内Wi-Fiはパブリック扱いのことが多い）。出なかった・拒否してしまった場合は、管理者のPowerShellで:

```powershell
New-NetFirewallRule -DisplayName "gakusai-pos 8443" -Direction Inbound -Protocol TCP -LocalPort 8443 -Action Allow
```

macOS：「システム設定 → ネットワーク → ファイアウォール → オプション」で Python の受信接続を許可します。

### スリープ・画面消灯・自動更新

- **PC3**：AC電源につなぐ。スリープを「なし」にする（Windows：設定 → システム → 電源、macOS：システム設定 → ディスプレイ／バッテリー）。Windows Update は「更新を一時停止」にしておく。
- **PC1（ノートPC）**：スリープと画面の自動オフを「なし」に。
- **PC2（スマホ）**：画面の自動消灯を最長（10分〜30分）にする。厨房・受付の画面は、対応端末では表示中に画面が消えないようにしています。画面が消えても、つけ直せば自動で再接続します。

## 7. 当日の手順

### 開店前（1日目の朝）

1. PC3で `uv run gakusai-pos serve` を起動し、管理画面を開く。
2. 「設定」：店名・営業日（1日目・2日目）・呼出番号の開始値・パスコード・USBメモリのバックアップ先（例 `E:\`）を設定。
3. 「商品」：商品名と価格（50円の倍数）を登録 →「QRカード印刷」で印刷し、点線で切る。作れる数が決まっている商品は「作れる数」を入れると、売れた分だけ減り0で自動売切になります。
4. PC1・PC2を接続（5章）。
5. **リハーサル**：「設定」でテストモードをオン → 何件か会計・調理・受渡・取消を試す → テストモードをオフ。テスト注文は売上に入りません。不要なら「注文」→「注文データの削除」で「テスト注文のみ」を削除。
6. ホームの「端末の接続状況」で受付・厨房が「接続中」になっていることを確認。

### 営業中の流れ

1. 受付：QRカードをかざす／商品ボタンを押す。まとめて頼まれたら「個数」の数字を押してから商品を追加。
2. 「会計へ」→ 表示された金券の枚数を受け取る →「受取確認」。
3. 大きく出た **呼出番号を紙の番号札に書いて渡す**（番号が出るまでは渡さない）→「次のお客様」。
4. 厨房：上から順に「調理開始」→ できたら番号札と照合して渡し「受渡完了」。
5. 間違えたら：会計前は「−」「削除」「クリア」。会計後は「履歴・取消」から取消し、金券を手で返す（厨房には赤い「取消」が出るので「確認」を押す）。厨房の押し間違いは「戻す」、受渡完了の押し間違いは「受渡済」一覧の「調理中に戻す」。
6. 売り切れたら厨房の「売切」で切り替え（受付に即反映）。

### レジ締め（各日の終わり）

1. 受渡前の注文が残っていないか厨房画面で確認。
2. 管理画面「売上・レジ締め」→ 営業日を選ぶと、その日の売上（金券の枚数）が出る。
3. 実際に数えた金券の枚数を入力して「記録」。差が表示・記録されます。
4. 「注文」タブの「注文CSV」「明細CSV」、「操作ログ」タブの「ログCSV」で保存し、「ホーム」の「今すぐバックアップ」。

呼出番号は営業日が変わると自動で開始値から振り直されます（日付はPC3の時計で決まります）。

### 閉店（2日目の終わり）

レジ締めの後、CSVとバックアップを保存してからサーバーを `Ctrl+C` で止めます。データは `data/pos.db` に残ります。

### 障害時

| 事象 | 対応 |
| --- | --- |
| QRが読めない | 商品ボタンで続ける。距離（20〜30cm）・角度・照明を調整 |
| カメラが使えない | Chromeのカメラ許可、他のアプリがカメラを使っていないか確認。ボタンだけで営業できる |
| 「保存に失敗しました。再送信しています」 | 自動で再送信します（二重登録はされません）。**番号が出るまで番号札を渡さない** |
| Wi-Fiが切れた／赤帯が消えない | 紙の代替手順へ（下記） |
| PC3が落ちた | 再起動して `uv run gakusai-pos serve`。受渡前の注文は復元される。URLが変わっていたら店舗に知らせる |
| PC3が復旧できない | 下記「別のPCで起動」 |

**紙の代替手順**：番号札と同じ番号の欄が並んだ記入用紙に、受付が商品と個数を書いて厨房へ渡します。復旧後、管理画面「注文」→「手入力」で営業日・会計時刻・呼出番号・個数を入れて登録すると、売上に反映されます。

**バックアップ**：サーバー起動中は5分ごとに `data/backups/` と、設定したUSBメモリの `gakusai-pos/` フォルダへ自動保存します（SQLiteのバックアップAPIを使用）。手動では管理画面の「今すぐバックアップ」、またはサーバーを止めずに:

```sh
uv run gakusai-pos backup
```

**別のPCで起動（PC3が復旧できない場合）**：

1. 別のPCにuvを入れ、このリポジトリ一式をコピーして `uv sync`。
2. USBメモリの `gakusai-pos/` から最新の `pos-YYYYMMDD-HHMMSS.db` を選んで復元:

   ```sh
   uv run gakusai-pos restore E:\gakusai-pos\pos-20261101-143000.db
   ```

3. `uv run gakusai-pos serve` で起動し、新しいURLでPC1・PC2をつなぎ直す（パスコードと商品は復元されたものが使えます）。

`restore` は置き換え前のDBを `data/backups/before-restore.db` に残します。必ずサーバーを止めてから実行してください。

## 8. 開発者向け

```sh
uv sync                 # 開発用の依存（pytest・httpx・ruff）も入る
uv run pytest           # テスト
uv run ruff check       # 静的チェック
uv run ruff format      # 整形
```

テストでは、金額計算（50円単位の検証）、状態遷移（不正な遷移・古い状態での操作の拒否）、二重送信の防止、PC3以外からの管理API拒否、端末認証、売上集計・レジ締め、注文の削除、WebSocket通知などを確かめています。

### 主なAPI

| メソッド | パス | 用途 | 端末 |
| --- | --- | --- | --- |
| POST | `/api/session` | パスコードと役割を送り端末を登録（Cookie発行） | PC1・PC2 |
| GET | `/api/products` | 商品一覧（売切含む） | 全端末 |
| POST | `/api/orders` | 会計確定（`client_uuid` で二重登録防止） | PC1 |
| GET | `/api/orders?status=open` | 受渡前の注文（＋未確認の取消） | 全端末 |
| GET | `/api/orders?status=day` / `delivered` | 当日の注文 / 最近受け渡した注文 | 全端末 |
| POST | `/api/orders/{id}/status` | 状態変更（`current` と `to`。現在の状態が一致するときだけ反映） | PC2 |
| POST | `/api/orders/{id}/cancel` | 取消 | PC1 |
| POST | `/api/orders/{id}/ack` | 取消表示の確認 | PC2 |
| POST | `/api/products/{id}/sold-out` | 売切切替 | PC2 |
| 各種 | `/admin/api/...` | 商品・設定・ログ・注文・集計・レジ締め・CSV・バックアップ | PC3のみ |
| WS | `/ws` | `order_created` / `order_updated` / `product_updated` / `settings_updated` の通知、10秒ごとの生存確認 | 全端末 |

### 仕様書からの補足

- `orders` に `cancel_ack_at`（厨房が取消表示を「確認」した時刻）を追加しました。複数の厨房端末や再接続時にも、取消表示が確認されるまで残るようにするためです。
- `events` に `terminal_id`（端末ごとのランダムID）を追加し、同じ役割の端末が複数あっても区別できるようにしました。
- 呼出番号は営業日ごと、かつテスト注文と本番注文で別々に振ります。
- QRの連続読取の抑止（R-03）は「同じコードが映像から消える（0.7秒見えない）まで、かつ前回の追加から1.5秒経つまで」追加しない、としています。
- 効果音はWebAudioで生成しているため、音声ファイルは同梱していません。
